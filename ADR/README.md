# ADR — Architecture Decision Records

This directory holds accepted architectural decisions for CreatorOS.

An ADR is a short, immutable record of a single architectural decision: the context that prompted it, the decision itself, and its consequences. Once accepted, an ADR is not edited — it is superseded by a new ADR if the decision changes.

## Structure

- [`templates/`](templates) — templates for creating new ADRs.

## Lifecycle

1. An RFC reaches consensus (see [`RFC/`](../RFC/README.md)).
2. One or more ADRs are created here to record the resulting decision(s).
3. If a decision is later reversed, a new ADR supersedes the old one; the original is kept, not deleted.

## Naming Convention

`NNNN-short-title.md`, using a zero-padded, sequential four-digit number (e.g. `0001-example-decision.md`).
